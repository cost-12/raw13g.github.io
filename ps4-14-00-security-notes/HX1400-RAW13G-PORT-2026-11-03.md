# HX1400 integration into RAW13G (2026-11-03)

## Scope

This change begins the FW 14.00 HX1400 runtime port from the local
`/home/thiago/silverps4hen/raw13` checkout into RAW13G.

The port uses the Silver runtime modules:

- `includes/js/hx1400_port.js`: route/kernel-base discovery.
- `includes/js/hx_kevent.js`: DCE/kevent chain, bridge, kernel patch and HEN payload stages.
- `includes/js/hx_tables.js`: FW 14.00-specific tables.
- `includes/payloads/HEN/hen.bin`: 562,240-byte payload used by the HX stage-10 loader.

The Silver `raw13/LICENSE` notice is preserved at the repository root as
`THIRD_PARTY_NOTICES-HX1400.txt`.

## Runtime integration

The RAW13G runner recognizes `?hx1400=1` only on firmware 14.00.
The homepage launcher now selects that route automatically for a detected
14.00 console and supplies stage3 through stage10 plus the direct HEN entry
flag, unless the query explicitly overrides those settings.

For 14.00, the homepage intentionally does not append the generic
`slots=2800000` or `attempts=1` values. It leaves those unset so
`jb.js` and `core.js` apply the firmware profile from `ps4_offsets.js`
(9,100,000 carrier slots and up to three bounded attempts).

After the existing WebKit primitive, userland base discovery, gadget checks,
and syscall-stub setup, the runner:

1. Imports `hx1400_port.js?v=hx1400-1` and calls `runHx1400(context)`.
2. Checks the runtime value in `globalThis.__HX_KBASE`. The route module
   deliberately returns `false` after successful discovery; the global
   KBASE value is its success hand-off.
3. Imports `hx_kevent.js?v=hx1400-1` and calls `runKevent({ ...context, kbase })`.
4. Maps the module's `fetchFile("hen.bin")` request to the bundled
   `includes/payloads/HEN/hen.bin` asset.
5. Treats only a literal `true` return from `runKevent` as successful
   completion.

The old RAW13G worker/socket kernel path remains disabled for FW 14.00.
HX1400 failures do not automatically reload or retry in the same boot; the
runner leaves the lock in the reboot-required state.

## What was intentionally not copied

- `core.js`, `mem.js`, and `int64.js` were not replaced by the Silver
  versions. RAW13G retains its local deferred SSV/history store and
  ADDROF refresh after heap grooming. Replacing those files would undo local
  fixes for history deserialization and stale fake-cell addresses.
- `hx_krw.js` was not copied into the runtime. In Silver it is not imported by
  the integrated runner, and it imports `hxBridge` from `hx_kevent.js`, where
  no such export is present in this checkout. The active path is implemented
  inside `hx_kevent.js`.
- The optional `ps4debug=1` branch was not made operational. Silver's
  `hx_kevent.js` fetches `ps4debug_silver.bin`, which is not present in
  the Silver repository inventory and was not copied.
- RAW13G's kernel offset policy remains explicit: 14.00 uses the WebKit family
  shared with 13.52, but the legacy kernel RVAs remain undefined. HX1400 uses
  its own `hx_tables.js` data.

## Module identity and cache

`jb.js` and `mem.js` now both import `core.js?v=13`, preventing two
independent ES-module instances of the primitive core.

The HTML entry imports `jb.js?v=15`. The AppCache revision is
`20261103-v56-hx1400-homepage-launch-profile` and includes the three
dynamically imported HX modules plus `hen.bin`.

## Validation completed

- JavaScript syntax checks passed for the runner, memory module, HX route,
  HX kevent module and HX tables.
- `npm test`: 42 passed, 0 failed, including a static check for the 14.00
  homepage launch parameters and preservation of the firmware groom profile.
- The offline-manifest hash test passed, including the new HX assets.
- CRLF-aware `git diff --check` passed.

The integrated HX chain has not yet completed successfully on the PS4.
Post-port local-host runs observed on 2026-11-03 stopped during Stage 1 with
`SSV-PLACEMENT-MISS` / `Unable to deserialize data` at `history-state`;
they produced no `HX1400-START`, KBASE, kevent, or payload markers. Those
runs used the older homepage defaults (2,800,000 slots and one attempt).
The v56 homepage/profile correction has been served locally but has not yet
been tested on hardware. The successful Sentrix screenshots remain reference
evidence from the external implementation, not proof that RAW13G has completed
the same chain.
